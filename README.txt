SmartSchedule — ЦЕНТРАЛЬНЫЙ СЕРВЕР

ЧТО ЭТО
Приложение работает как единая школьная система. Если задан DATABASE_URL, все устройства работают с одной PostgreSQL-базой. Если DATABASE_URL не задан, используется локальная SQLite-база.

ЛОКАЛЬНО НА WINDOWS
1) Запусти INSTALL.bat один раз.
2) Запусти START.bat.
3) Для телефона в той же Wi-Fi используй адрес, который напечатает чёрное окно.

ИНТЕРНЕТ / ОБЩАЯ ССЫЛКА
Для доступа из разных Wi-Fi нужен сервер в интернете. Эта сборка подготовлена для Render + PostgreSQL/Supabase.
1) Создай PostgreSQL-базу.
2) Получи её DATABASE_URL.
3) Загрузи этот проект в GitHub.
4) Создай Web Service на Render.
5) Build Command: pip install -r requirements.txt
6) Start Command: gunicorn app:app --workers 1 --threads 4 --timeout 120
7) Добавь переменные SMARTSCHEDULE_SECRET и DATABASE_URL.
8) После запуска Render даст публичный адрес вида https://имя.onrender.com.

ВАЖНО О ДАННЫХ
Локальный school.json используется только как стартовые демонстрационные данные/аварийная копия. При наличии DATABASE_URL источником истины является центральная PostgreSQL-база.

СИНХРОНИЗАЦИЯ
Страницы периодически проверяют номер ревизии центральной базы. Если другой пользователь изменил данные, страница обновляется автоматически, когда это безопасно.

КАЧЕСТВО РАСПИСАНИЯ
Генератор старается получить 0 окон. Допустимый максимум — 1 окно. Дополнительно запрещаются: более 2 сложных предметов уровня 3 в день, более 2 тяжёлых подряд и превышение лимита баллов нагрузки дня. Если ограничения несовместимы, система помечает результат как требующий проверки и показывает неразмещённые уроки.

ШКАЛА СЛОЖНОСТИ
1 — лёгкий; 2 — средний; 3 — сложный.

EXCEL
В веб-расписании показываются предмет, учитель и кабинет. В скачиваемом Excel учитель намеренно НЕ выводится: только предмет и кабинет.

БЕЗОПАСНОСТЬ
Для публичного сервера обязательно используй непредсказуемый SMARTSCHEDULE_SECRET и не публикуй DATABASE_URL. Для реальной школы нужны авторизация, резервное копирование и разграничение ролей.
